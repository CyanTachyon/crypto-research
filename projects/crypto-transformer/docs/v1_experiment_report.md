# V1 实验报告：用 Transformer 预测加密货币价格方向

## 摘要

我们训练了一个 Encoder-only Transformer，使用币安 1h K 线数据预测 ETH/USDT 和 BTC/USDT 下一小时的价格方向（上涨/下跌/横盘）。模型在 ETH/USDT 上达到了 **70.9% 的准确率**，在 BTC/USDT 上达到了 **77.2% 的准确率**，但这些数字具有误导性。模型几乎只预测"横盘"（多数类），无法有效预测方向性走势。XGBoost 基线模型的表现与 Transformer 持平甚至更优，这表明 1h OHLCV 数据中可用于方向预测的信号极其微弱。

**结论：V1 证明了直接将 Transformer 应用于 1h 加密货币数据的价格方向预测，无法产生可用的交易信号。**

---

## 1. 实验设计

### 1.1 目标
- **第一阶段（本次实验）：** 将下一小时价格方向预测作为三分类问题（上涨/下跌/横盘）
- **目标：** 确定 Transformer 能否从 OHLCV + 技术指标特征中学到有意义的模式

### 1.2 假设
如果模型在方向性预测（具体指上涨/下跌类别，而非横盘）上能取得 >60% 的准确率，则预测结果可作为交易信号使用。通过与 XGBoost 和简单策略的基线对比，可以判断深度学习是否带来了额外价值。

### 1.3 交易对与数据来源
| 交易对 | 来源 | 周期 | 行数 | 时间范围 |
|------|--------|-----------|------|------------|
| ETH/USDT | Binance | 1h | 56,226 | 2020-01-01 to 2026-06-02 |
| BTC/USDT | Binance | 1h | 56,226 | 2020-01-01 to 2026-06-02 |
| WETH/USDC (Base) | GeckoTerminal | 1h | 1,049 | 约 6 周 |
| cbBTC/USDC (Base) | GeckoTerminal | 1h | 1,004 | 约 6 周 |

**备注：** GeckoTerminal 的免费 API 仅提供约 6 周的小时级 OHLCV 数据，不足以用于训练。币安数据被用作主要数据源。由于数据限制，原计划使用 Base 链 DEX 数据的方案在训练阶段不可行。

### 1.4 训练集/测试集划分
- **训练集：** 2020-01-01 至约 2025-09-01（训练期的 80%）
- **验证集：** 约 2025-09-01 至 2025-12-01（训练期的 20%）
- **测试集：** 2025-12-01 至 2026-06-02（最后约 6 个月，严格保留）
- 按时间顺序划分，无数据泄漏

## 3. 模型架构

### 3.1 Transformer 配置
```
CryptoTransformer(
  input_proj: Linear(17, 128)
  pos_encoder: SinusoidalPositionalEncoding(128)
  encoder: TransformerEncoder(
    TransformerEncoderLayer(d_model=128, nhead=4, dim_ff=512, dropout=0.2, norm_first=True)
    × 4 layers
  )
  classifier: Sequential(
    LayerNorm(128),
    Linear(128, 64), GELU(), Dropout(0.2),
    Linear(64, 3)
  )
)
Total parameters: 804,099
```

### 3.2 设计理由
- **Encoder-only**（非 Decoder-only）：分类任务受益于对完整上下文窗口的双向注意力
- **小型模型（约 800K 参数）：** 金融时间序列信噪比低，大模型容易过拟合
- **norm_first=True：** Pre-norm 架构训练更稳定
- **上下文长度 48：** 48 根 1h K 线提供约 2 天的市场上下文
- **最后时间步池化：** 对最近一根 K 线预测标签

回测引擎产生了 **零笔交易**，因为模型对方向性预测的置信度极少超过 0.6 的阈值。预测置信度的中位数约为 0.51（对于三分类来说仅略高于随机），而且模型主要预测"横盘"且置信度中等。

即使将阈值降至 0.45，方向性预测的准确率仍然太低（上涨/下跌的精确率约 22%），在扣除交易成本后无法产生盈利交易。

## 6. 分析与关键发现

### 6.1 模型失败的原因

1. **信噪比极低：** 1h 加密货币收益率接近随机。模型没有统计上可利用的模式可以学习。

2. **分布偏移：** 训练数据中约 35% 为方向性走势（上涨+下跌），但测试数据中仅约 25%。模型学到的训练期模式无法泛化。

3. **特征局限：** OHLCV + 技术指标本质上是滞后指标。当信号出现在指标中时，市场已经发生了变动。

4. **类别不平衡：** "横盘"类占主导（65-81%），导致模型偏向于安全的预测。类别权重有所帮助，但无法克服信号根本性缺失的问题。

5. **XGBoost 与 Transformer 表现相当：** 简单的树模型表现相近，说明 Transformer 的注意力机制并未发现有意义的时序模式。在这种粒度和这些特征下，根本没有什么可发现的。

### 6.2 哪些方面有效

- 训练基础设施是可靠的：干净的数据管道、合理的时间划分、早停机制
- 模型训练稳定，未出现 NaN 损失或梯度爆炸
- 类别加权损失函数避免了模型完全退化为多数类预测
- 回测引擎正确模拟了手续费和滑点

### 6.3 与已有研究的比较

这些结果与机器学习在金融领域的更广泛文献一致：
- 简单模型（线性回归、XGBoost）在标准金融预测任务上通常与深度学习持平甚至更优
- Transformer 擅长高维、高信号领域（NLP、计算机视觉），而非低信号金融时间序列
- 学术论文中报告的加密货币预测高准确率，往往存在隐蔽的数据泄漏或在合成/筛选数据上测试的问题

## 7. 对 V2 的建议

基于 V1 的发现，以下改进可能提升结果：

### 7.1 数据与特征
- **添加订单簿数据：** 深度、买卖价差、订单流不平衡
- **多时间周期输入：** 将 5m/15m/1h/4h 特征组合到单个 token 中
- **链上特征：** Gas 费用、活跃地址数、交易所流入/流出
- **情绪特征：** 社交媒体情绪、资金费率、清算数据
- **跨资产特征：** 交易 ETH 时考虑与 BTC 的相关性，反之亦然

### 7.2 任务重构
- **回归而非分类：** 预测实际收益率而非离散化的方向
- **更长的预测周期：** 预测 4h 或 24h 收益率而非 1h（更多信号，更少噪声）
- **波动率预测：** 预测已实现波动率，这是一个更可行的目标
- **排序：** 对资产的预期收益率进行排序，而非做绝对预测

### 7.3 架构变更
- **更大的上下文窗口：** 尝试 128-256 个时间步（5-10 天）
- **Temporal Fusion Transformer：** 专为多周期时间序列设计
- **Mamba/State Space Models：** 对长序列更高效
- **多资产预训练：** 在所有加密货币交易对上联合训练，然后微调

### 7.4 训练策略
- **Focal Loss：** 通过聚焦困难样本更好地处理类别不平衡
- **课程学习：** 从简单时期（趋势行情）开始，逐步加入波动时期
- **对抗验证：** 确保训练集与测试集的分布相似性
- **滚动验证：** 使用滚动窗口评估替代固定划分

---

## 8. 结论

V1 证明了 **将 Transformer 直接应用于 1h OHLCV 数据进行价格方向预测，无法产生有用的交易信号。** 模型表面上"70%+ 的准确率"完全来自对多数类（"横盘"）的预测，其方向性预测精确率（约 22%）远低于扣除成本后实现盈利交易所需的水平。

这一阴性结果本身具有价值。它建立了一个严格的基线，并突显了金融时间序列预测的根本性挑战。后续实验应重点关注更丰富的特征、不同的预测目标（波动率、相对排序），以及可能不同的数据粒度。

## 9. 可复现性

### 环境
- Python 3.12.13 (venv)
- PyTorch 2.9.1+cu128
- 1× Tesla V100 32GB (CUDA_VISIBLE_DEVICES=4)
- Arch Linux, CUDA 13.2

### 数据
- 通过 CCXT 获取的 Binance ETH/USDT 和 BTC/USDT 1h OHLCV 数据
- 以 Parquet 格式缓存在 `data/raw/` 目录

### 命令
```bash
source .venv/bin/activate
CUDA_VISIBLE_DEVICES=4 python scripts/train.py
python scripts/plot_results.py
```

### 输出
- `data/results.json` — 包含指标、混淆矩阵、训练历史的完整结果
- `data/checkpoints/best_model.pt` — 最佳模型权重
- `docs/figures/` — 训练曲线、混淆矩阵、对比图表
