# 20 USDC / BTC、ETH 永续策略：冻结实验方案 v1

冻结日期：2026-09-24。本方案先于本轮策略收益计算编写；代码、数据与最终结果各自记录 SHA-256。此前审计发现的正收益依赖收益截断、错误滑点或错误记账，本轮不得沿用其盈利结论。

目标是淘汰缺乏证据的策略，并检验一个小额、低频、可做多做空的执行流程。研究、回测和公开行情模拟均不发送真实订单。本方案不是盈利保证；没有通过的策略也是完整实验结果，不能为了得到赢家而放宽约束。

## 1. 预先固定的数据、区间与选择纪律

- 主数据：Hyperliquid 原生 BTC、ETH 小时 OHLC 与实际逐小时 funding rate，使用可获得的最近约 4,900 根**已完成**小时线。存储原始时间戳、来源、获取时间、缺失/重复检查、数量精度快照与哈希。当前未完成小时不能成为信号输入。
- 时间全部使用 UTC；BTC/ETH 取共同完整时段。不得用向后填充修复缺失价格。缺失期间停止新开仓并记录；已有仓位的不确定成交不能凭空按止损价成交。资金费缺失须显式报错或令该区间无效，不能填成零。
- 前 336 小时仅做统一指标预热。其余连续小时按时间分成 50% 开发、25% 选择、25% 最终保留检验，切点向下取整到完整 4 小时边界。以数据文件为依据把实际日历日期写入运行清单，第一次跑收益前固定。各段重置为 20 USDC、空仓及独立风控状态；指标允许使用该段之前的已完成历史。
- 开发段只用于账本、单位和程序正确性诊断，不调整下面八个候选参数。选择段只选择一个候选。最终段只检验选中候选，其他候选的最终段收益不用于换人；没有合格候选时最终段保留，不挑最终段赢家。
- 本轮“保留检验”最多是相对本轮选择算法没有使用的历史样本。先前多次研究已经观察过部分历史，最近数据也不是未来数据；不得称其为真正前瞻或从未被人查看的独立样本。
- 原有 Binance 2020–2026 数据可以用于跨市场、不同周期的敏感性诊断，必须独立标注。其日频聚合资金费和 USDT/交易场所差异不能替代 Hyperliquid 成交验证，也不能用于本轮二次调参。
- 冻结后如发现影响收益的代码错误：保留旧结果、记录错误及修复，重算是修正而非“新独立实验”；被看过的最终段不再具备原来的保留地位。新的策略假设需要另一个版本和新的未来窗口。

## 2. 仅八个候选

所有指标只用截至当前已完成小时的数据；每 4 小时决策，最早下一小时开盘加不利滑点成交。ATR24 是最近 24 根 true range 的算术平均，true range 包括与前收盘的跳空；EMA 用首个完整窗口的 SMA 初始化。每个候选同时检查 BTC/ETH，空仓时仅选择强度最大的合格信号；强度相同优先 BTC。持仓期间不为追逐另一个币的强度切换持仓。

| 候选 ID | 已固定假设 | 新开仓方向 / 强度 |
|---|---|---|
| `breakout_72` | 过去 72 小时通道突破有延续性 | 收盘高于前 72 根最高价做多、低于最低价做空；通道不含当前根。强度为收盘距通道中点的绝对值 / ATR24 |
| `breakout_168` | 同上，168 小时 | 同上 |
| `breakout_336` | 同上，336 小时 | 同上 |
| `momentum_72` | 过去 72 小时方向有延续性 | `close[t] - close[t-72]` 正则多、负则空；强度为差值绝对值 / ATR24 |
| `momentum_168` | 同上，168 小时 | 同上 |
| `momentum_336` | 同上，336 小时 | 同上 |
| `ema_24_120` | 快慢趋势方向有延续性 | EMA24 高于 EMA120 做多，低于则空；强度为差值绝对值 / ATR24 |
| `range_48` | 平缓趋势中的极端偏离有回归性 | 最近 48 根收盘的总体标准差构造 z；仅当 `abs(EMA120[t]−EMA120[t−24])/ATR24 <= 0.5`，z≤−1.5 做多、z≥1.5 做空；强度为 `abs(z)` |

共同退出：相反信号、保护止损、持有满 168 小时，或风控触发。区间回归额外在价格回到 SMA48 时退出：多仓 `close>=SMA48`，空仓 `close<=SMA48`；无入场信号不等于触发均值退出。其他候选的零方向信号不主动退出。退出后至少等待 4 小时，同一小时不反手；不加仓，不摊平，不把信号或收益截断当作真实止损。

## 3. 20 USDC 账户及成交模型

- 初始权益 20 USDC；只允许一个 BTC 或 ETH 永续仓位，USDC 为抵押与闲置资金。新仓名义上限 `min(15 USDC, 0.75×权益)`，总毛名义价值不得超过权益；杠杆上限 1 倍。平仓后才能切换币种或方向。
- 初始止损距离为信号时点的 `3×ATR24`。单笔计划损失预算为当前权益 1%，计入预估开仓/平仓费用与滑点；按风险预算及名义上限中的较小值计算数量，再按交易所 `szDecimals` **向下**舍入。舍入后不足 10 USD 不交易；不能向上凑单、提高杠杆或放宽止损来制造样本。
- 移动止损只能使用上一个已完成小时的收盘和 ATR，朝降低风险的方向更新，不能使用尚未发生的同根高点/低点。最大持有时间、止损和日风险约束对所有候选相同。
- 小时 OHLC 内触及止损，正常触及按止损价加不利滑点；开盘已跳过止损，按更差的开盘价加不利滑点。若任何实现同时有两个相反触发，使用不利顺序并披露。没有 L2 历史时，小时开盘成交只是近似，不是 IOC 一定成交的证明。
- 多头买高卖低、空头卖低买高。手续费对每次实际开仓和退出分别收费，不因为退出盈亏或交易统计而重复扣账。累计净盈亏必须等于现金变化，权益=现金+按市值计算的未实现盈亏。
- UTC 日内权益亏损达到日初权益 3% 后，当日禁止新开仓并继续管理现有仓位；以已实现和未实现合计权益判断。高水位回撤达到 10% 后关闭仓位、锁定停止，期间禁止自动重置并续跑。跳空及执行失败可能超出触发预算，不能把权益或亏损截断到阈值。
- 初始 20 USDC、10 USD 最低订单、1% 风险预算意味着交易机会会非常稀少：例如 10 USD 名义仓位、3% 止损，仅价格风险已达 0.30 USD。这类订单必须拒绝；不交易不是程序失败。

## 4. 费用、资金费和压力情景

基础情景每侧 taker 4.5 bps + 滑点 2 bps；中度每侧 6+5 bps；重度每侧 9+10 bps。三个情景均重新模拟账户、数量约束及停机状态，不能事后从最终收益减去平均费用。假设一律 taker，不借用 maker 费率、返佣或挂单必成交的好处。

实际逐小时资金费使用当时已持有的带符号数量：`现金变化 = −signed_qty × oracle_price × funding_rate`，正费率由多头支付、空头收取。资金费只在真实结算时点计入；信号不能读取未来结算率。若数据只有成交 OHLC 和费率，则可用对应时点成交价格近似 oracle，但必须在报告中标注，不能声称精确复现交易所账本。额外敏感性应去掉所有资金费收入、将支出加倍；若没有实现该敏感性，列为未完成可靠性条件。历史 oracle、精确触发价格及 L2 缺失均是从回测走向实盘前的限制。

## 5. 比较对象、选择规则与失败条件

每个区间同时报告：留在 USDC（0 毛收益、无虚构利息）；相同初始资金下买入并持有 BTC；买入并持有 ETH。被动永续基准同样使用数量精度、费用、资金费与明确的初始名义敞口；不把杠杆不同的结果直接混比。策略目标首先是成本后正收益与可控损失，不要求在单边牛市里跑赢满仓 BTC；必须显示落后被动策略的代价。

统一指标：净收益（USDC 与百分比）、最大逐小时/日内可观察回撤、最坏单日、完整闭合交易数、总成交次数、胜率、平均净盈亏、手续费、资金费、换手、持仓时间比例、拒绝开仓次数及原因、风控停机时间。日收益 Sharpe 仅作描述；样本短、强自相关时不据其单独宣布显著。

选择段预先规则：基础和中度压力两个场景各自收益为正、最大回撤低于 8%、至少 10 笔完整闭合交易且未发生账户风控停机，才有资格被选择。按**中度压力净收益**从高到低选择；完全相同则按较小最大回撤、较低换手、上表候选顺序依次打破并列。无人通过则记录“不具备可选策略”，不能偷偷改用最终段结果。

运行前口径补充（2026-09-25，尚未计算策略结果）：高水位按小时开盘/收盘观察，回撤额外检查持仓期间不利价格或实际止损成交；未假设同根有利极值先出现，所以不等同于逐笔真实回撤。日亏损限制一旦触发锁定到下一 UTC 日。收盘后移动止损用刚完成的收盘价及同根 ATR，只对下一小时生效。额外一小时延迟场景只延迟入场/方向决策，不延迟既有止损。保留期另要求资金费压力及延迟压力收益为正。以上口径均在首次运行清单中固定。

选中候选最终段的继续研究条件：基础、中度及重度压力下成本后净收益均为正；基础最大回撤低于 8%；至少 20 笔完整闭合交易；资金费不利敏感性下仍不依赖融资收入盈利；非重叠子区间大多数为正。如果任一条件未测或样本不足，结论就是尚未通过。通过这些门槛只取得继续公开行情模拟的资格，未取得真实交易资格。

若最终段至少 90 天，分别列三个不重叠 30 天子区间；预计本轮 25% 最终段仅约 47 天，因此无法满足三段 30 天验证，应显示现有完整 15 天块（至少两块）与尾段，明确覆盖不足。不能把滚动重叠窗口称作独立复验。区间结果、费用压力与 BTC/ETH 归因一起展示，避免总收益掩盖一次偶然交易。

## 6. 实时模拟与实盘审批前的必要证据

经济表现和执行正确性是两类不同条件。历史回测无法检验真实网络、撮合、失败恢复，模拟盈利也无法证明存在稳定优势。

1. 离线故障测试必须覆盖：滑点方向、最低订单/数量精度、资金费正负、开平仓费用对账、累计仓位约束、拒单、部分成交、超时但已经成交、重复回报幂等、重启恢复、平仓失败后的剩余保护、行情过期以及停机锁。禁止用“请求无异常”代表成交成功。
2. 选中候选和执行代码冻结，使用未来到来的 Hyperliquid 公开行情至少观察 30 个日历日且记录 20 笔完整模拟交易，以较晚达到者为准。模拟应保存决策时间、可用数据、可执行盘口、拒绝与假设成交记录，日常不为短期收益修改参数。没有足够信号就延长观察，不能制造交易。该门槛检验运行流程，仍不足以证明长期盈利。
3. 真实 API 行为需要隔离的测试环境/故障模拟验证；公开行情纸面成交不能证明交易所实际接受订单或保护单可靠。维护独立只读采集器，任何可发单适配器默认禁用且不加载私钥。
4. 最终向用户展示冻结策略、逐项门槛、净值曲线、最大损失、未知限制及具体 20 USDC 配置。只有工程与研究条件通过后，才询问是否授权真实小额试运行。用户尚未明确接受最大回撤和杠杆：本方案数值只是研究边界，不应暗中应用到账户。

即使所有条件通过，有限样本、市场变化和模拟成交误差仍然存在。最多只能得出“在所列假设和已观察数据下，通过了当前检验”，不能承诺盈利或宣称已确保安全。
